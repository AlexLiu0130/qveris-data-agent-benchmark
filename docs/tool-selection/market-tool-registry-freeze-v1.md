# Market Tool Registry v1 freeze

This freeze records the first real QVeris Execute evidence by `market × asset_type × scenario_id`, not a three-direction-to-one-tool shortcut. The machine-readable registry is [qveris-market-tool-registry-v1.json](../scenarios/qveris-market-tool-registry-v1.json). Its complete V1 grid is `US, SSE, SZSE, HKEX × 22 base scenarios = 88 cells`.

`selected_provisional` is deliberately below an active runtime binding: it means one narrow response shape has passed a controlled Execute, while accuracy, freshness, market/session semantics, coverage, stability, and a comparable ranking remain open. `gap`, `unverified`, and `rejected` must stay visible to the Agent/Router admission process; there is no implicit cross-market reuse or fallback.

Control inputs are kept outside provider performance statistics. For example, the invalid Finnhub request without `symbol` is recorded as input-validation evidence, not quote latency/cost/reliability. A reported HKEX calendar success is nevertheless rejected because its `result.data` lacked the contract's `trading_date` and `is_trading_day` fields. The controlled `600519.SH` evidence belongs only to SSE; SZSE is catalog-only and has no copied selection, latency, or cost. HKEX split evidence is a `split_only` candidate inside general `historical.corporate_actions.v1`, not a general action binding. Extended-hours is `not_applicable` for SSE, SZSE and HKEX as a product-taxonomy decision, not tool evidence.

Before promoting any entry, run the frozen representative request against each candidate in the same market and scenario, retain the provider receipt, independently check required fields and data correctness, then rank successful candidates by the agreed quality, latency, and cost policy. This document contains no raw results, execution IDs, balances, or credentials.

The paired US quote result remains unresolved: close/change agree after permitted rounding, but sessions and timestamps differ and the requests were not the same observation time. Finnhub matching the same-date Tiingo EOD close does not establish real-time freshness. The paired US EOD result also remains unresolved: OHLC agrees (low within 0.01), but volume materially conflicts; because the base contract includes OHLCV, neither tool is selected.
