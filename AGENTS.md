# Project rules

- Keep three benchmark suites, with 100 cases per suite.
- Each runtime evaluation uses one agent only; Search and Inspect are not allowed.
- Each case permits one structured output and one tool execution.
- Evaluate against four agreed benchmark metrics; define their names and calculations before adding cases or scoring code.
- Never commit credentials, tokens, raw result artifacts, or other secrets.
- Do not deploy to production without separate, explicit authorization.
- Keep changes minimal and avoid choosing a language stack or scaffolding before it is needed.
